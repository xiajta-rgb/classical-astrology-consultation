# 知识插件化审查

结论：当前已经具备“核心体系 + 外接知识”的雏形，但原先的 `registry.json` 主要是资料登记表，还不是可稳定调用的插件层。现在补上声明式插件契约、依赖/版本/激活边界、检索索引和只读查询入口。

## 分层

- `natal-core`：现有 NATAL-1.0，始终先运行，是唯一可以形成主责任链和行星审计的核心层。
- `multi-significator-composition`：核心组合编排层，把多条征象抽象为汇聚、冲突、瓶颈、反馈和轴线转译；它负责综合，不新增证据。
- `core-natal-method`：两份附件蒸馏出的通用方法卡，显式主题调用，最多作为 C 级辅助证据。
- `house-ruler-flow`：144 条有向飞星/宫主流向，候选插件，显式调用。
- `mutual-reception-matrix`：78 个宫位对经验假设，辅助插件，必须经过严格互容/纳入审计。
- `timing-boundary`：时间技术清单，保持 inactive；没有明确时限问题和完整时间数据时不会被加载。

## 已具备与补齐

已有：模块内容、来源哈希、过滤蒸馏、证据等级上限、反证/护栏、核心体系先行和定时模块禁用。

补齐：统一插件契约、依赖和冲突字段、版本及回滚指针、激活谓词、按主题/模块/宫位的检索索引、只读查询器和架构检查器。

## 调用原则

先调用 `natal-core`，再按问题主题显式加载扩展。插件只返回带 `card_id/source_ids/grade_cap/safety_gate` 的证据卡和 deferred 项，不得覆盖 Chart Facts、责任链、typed reception 或既有核心结论。

## 断事效用门槛

星座、行星和宫位的本质释义只提供定义，不直接构成结论。插件必须声明 `judgment_utility`、`event_domains` 和 `event_mechanism`，并能把征象连接到责任链、现实机制和可观察事件表现。只有背景说明、不能增加推理或预测价值的内容，标记为 `context_only` 或 `deferred`，不进入核心判断；重复或遮蔽关键征象的模块应降权、退出检索或退役。
