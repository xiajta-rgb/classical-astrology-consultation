# Event-cluster retrieval policy

The event layer is a second index, not a replacement for the canonical
significator cards.

## Event taxonomy

The current registry contains 15 clusters:

- money windfall and large business profit
- sibling illness, disability, or death
- spouse/parent loss and grief
- chronic illness, treatment, or caregiving
- religion and spiritual practice
- business partnership and client network
- romance and dating
- marriage and long-term commitment
- relationship conflict, separation, or divorce
- friendship, community, and social network
- employment, workload, and workplace routine
- career direction, promotion, and public status
- children, parenting, and legacy
- academic research, teaching, and higher education
- family, property, and inherited resources

## Retrieval routes

| Task | Entry point | Required return path |
|---|---|---|
| Natal structure | Significator-first | House -> ruler -> state -> event translation |
| Real-world event validation | Event-first | Event -> candidate cards -> chart facts -> counter-test |
| Relationship comparison | Dual-entry | Significators and event cluster are compared separately |
| Prediction/timing | Event-first then timing | Event -> natal chain -> explicitly activated timing method |

## Anti-double-counting rule

An event link is a retrieval hint only. It is not an independent testimony. The
same planet, ruler, aspect, or house responsibility must be deduplicated before
confidence is increased. Medical, mortality, reproductive, and legal outcomes
remain gated and require real-world evidence plus the appropriate timing or
professional boundary.
