# CET 星盘接口适配说明

> 版本：CET-API-1.0（2026-08-14）

## 结论

可以。`https://cet.pythonanywhere.com/` 的前端公开调用了以下只读接口：

```text
GET https://cet.pythonanywhere.com/api/calculate-ephemeris
```

接口根据出生日期、时间、地点和时区计算星盘，返回行星黄经、宫位、轴点、宫头、相位、福点以及站点自己的接纳/飞宫候选信息。它不能把一份已经写好的“太阳天蝎 4 宫……”反向提交并验证；要复核那份清单，仍需要原始出生资料和计算设置。

## 请求参数

最小请求应包含：

```text
year, month, day, hour, minute, lat, lon
```

建议同时传入：

```text
tz=8
house_system=P
city=城市名（可选）
```

站点当前把 `P` 返回为 `Placidus`。出生时间、时区、坐标、黄道体系和宫制必须在原始资料中固化；如果任一项不确定，不得把临界宫位或相位写成确定事实。

示例（仅为公开接口测试，不是任何人的个人资料）：

```text
https://cet.pythonanywhere.com/api/calculate-ephemeris?year=1990&month=1&day=1&hour=12&minute=0&lat=39.9042&lon=116.4074&tz=8&house_system=P
```

## 返回字段到本命数据契约的映射

| 接口字段 | 可直接得到的内容 | 本项目处理方式 |
|---|---|---|
| `ephemeris` | Sun–Pluto、节点、Chiron、Juno、Fortune 的黄经、星座、度数、宫位等 | 作为原始行星/点事实；七曜先进入古典核心，外行星与小点标记为辅助 |
| `axes` | Asc、MC、DSC、IC 的黄经、星座、度数 | 写入 Chart Facts；29°或0°附近触发边界风险 |
| `house_cusps_detail` | 12 个宫头的黄经、星座 | 计算宫主、飞宫和主题责任链 |
| `aspects` | 两点、相位类型、角度、orb | 保存原始相位；古典核心须重新筛选七曜、应用/分离和允许容许度 |
| `Fortune`（位于 `ephemeris`） | 福点星座、度数、宫位 | 作为 Lot of Fortune 辅助证据，并记录计算设置 |
| `mutual_receptions` | 站点生成的接纳/宫主关系描述 | 仅作候选线索，不能直接当作严格的古典接纳或互容 |
| `visualization_data` | 前端归一化的可视化行星列表 | 可作显示层，不作为唯一事实源 |

## 四类目标信息能否获得

1. **行星宫位：可以。** 从 `ephemeris` 或 `visualization_data` 读取星座、度数和 `house_number`。上升从 `axes.asc` 读取。
2. **相位关系：可以。** `aspects` 提供行星对、相位名和 orb；需要本地按项目规则去重、判断应用/分离，并区分古典与现代层。
3. **宫头星座与飞宫：宫头可直接获得，飞宫需推导。** 接口返回宫头星座，但“X宫主落Y宫”是把宫主星定位到其实际落宫后计算的派生字段，不能把前端文案当作接口原始字段。
4. **接纳/互容：只能部分直接获得。** 站点返回的 `mutual_receptions` 是站点自己的候选描述，测试中出现重复和泛化的“X宫主落Y宫”文案，未必包含尊贵类型、方向、实际相位或应用状态。严格古典层必须由本地规则独立重算：守护/擢升/三分/界/面 → 方向 → 是否有实际相位连接 → 应用或分离 → 是否确属双向互容。

## 对用户所列清单的复核边界

用户给出的太阳、月亮、宫位、相位和互容清单，不能仅凭 URL 验证为“同一张盘”。至少需要：出生日期、准确出生时间（含时间精度）、出生地点或经纬度、时区、黄道体系、宫制，以及节点采用真/平均节点的约定。特别是“上升巨蟹29°”属于高边界风险：几分钟误差可能改变上升度数和部分宫位判断。

## 标准化流程

```text
GET 原始 JSON
  → 保存 input 与 raw_response
  → 归一化 planets / axes / houses / aspects / fortune
  → 本地计算宫主与飞宫
  → 本地重算严格接纳与互容
  → 七曜古典核心与现代辅助层分离
  → NATAL-1.0 Chart Facts / 反证 / 质量门
  → 生成可追溯本命文档
```

对应的只读适配脚本为 [`scripts/cet_api_client.py`](../scripts/cet_api_client.py)。脚本不保存凭据、不写入远端，只负责请求、字段校验和 UTF-8 标准化输出。
