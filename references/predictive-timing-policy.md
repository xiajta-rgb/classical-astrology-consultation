# 推运统计与月亮触发器政策

## 1. 算法口径隔离

每次推运输出必须声明 `calculation_profile`，至少区分：

- `project_local_ephh_secondary_v1`：次限，日年法；
- `project_local_ephh_tertiary_v3_sidereal`：三限，恒星月法（27.321661日），无额外锚点，当前默认；
- `project_local_ephh_tertiary_v2_synodic_anchor1`：中间校准口径，朔望月法（29.530588853日）并加1个推进日锚点，仅用于对照；
- `project_local_ephh_tertiary_v1`：旧三限日历月法，仅用于审计对照，不得与 v2/v3 混用；
- `project_local_ephh_solar_arc_v1`：太阳弧；
- `project_local_ephh_transit_v1`：行运；
- `user_declared_external`：用户提供的外部软件结果。

不同 profile 的黄经、相位日期、应用/分离状态不得混合。若同一征象在不同 profile 下不一致，必须输出 `profile_mismatch`，先对齐出生时间、推进公式、时区、黄道和目标对象，再进入解释层。

## 2. 月亮优先门禁

次限月、三限月和行运月亮必须先于其他行星完成扫描。每个目标窗口都要检查月亮对：

- 本命太阳、月亮、水星、金星、火星、木星、土星；
- 天王、海王、冥王和交点（标记为辅助层）；
- 本命上升、中天。

合相、刑相、冲相属于第一优先级；拱相、六合属于第二优先级。月亮硬相位清单未完成前，不得发布该窗口的阶段判断。

月亮接触必须回映到本命盘，而不是只读取推运盘自身宫位：例如次限月亮合本命6宫木星，
应按“本命6宫木星被激活”解释；推运盘中月亮所在宫位只能作为辅助背景。次限月亮负责
月度至季度级的中期落地，三限月亮负责周日至月度级的短期触发。两者必须记录精确日期、
容许度、入相/出相、算法 profile、被触发的本命行星、其本命宫位及宫主职能。

多年度请求必须按五年区间拆分，再在每个区间内列出次限月和三限月的合/刑/冲；任何一个
已扫描出的月亮硬相位未进入解读，视为推运报告不完整。

行运通过 `calculate_predictive("transit", ...)` 进入统一接口；窗口扫描使用
`scan_timing_window`，需要精确时刻时再调用 `refine_aspect_contacts`。粗扫描步长、精修方法和
最终容许度必须写入交付物，不能把日级扫描结果直接表述成精确发生时刻。

## 3. 容许度与方向

统一采用“入三出一”：入相不超过3°，出相不超过1°。精确相位单独标注。应用/分离必须由相邻时间点的角距变化确认，不能凭静态黄经猜测。

## 4. 完整性原则

现代外行星不能独立升级古典核心证据，但必须进入候选扫描并标记 `auxiliary_context`；“不能独立定论”不等于“可以不扫描”。

## 5. 发布前检查

推运报告必须先展示：算法 profile、月亮硬相位、其他核心相位、辅助相位、口径冲突和缺失数据。任何一个月亮合/刑/冲被遗漏，视为报告失败而不是普通降级。
